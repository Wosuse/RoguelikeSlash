# M6 实施计划与 V0.5 评审

日期：2026-11-15。状态：P0～P4 已实现并通过 70 项 Unity 集成检查；P5、P6 待实施。
依据：用户提供的 `roguelike_M6_roguelike_build_design_v0_5.md`，并对照当前工作区代码。文档中的“已确定”为设计稿声明，不自动覆盖用户此前明确要求；冲突见下文。

## 1. 目标与范围

建立“战斗 → 金币/经验 → 升级选择 → 武器和属性构筑 → 随机商店 → 返回战斗”的单局循环。
保留现有技能交互、融合操作、动画与场景表现。首批武器飞镖、飞刀、弓箭，统一 +3 封顶；元素、召唤、附魔、三技能融合及局外养成不进入本轮。

## 2. 当前代码与差距

- `ArenaPrototype.Combat.cs` 已有敌人/弹丸池、三类攻击行为、预警与死亡处理；敌方生命、伤害和友方弹丸命中伤害仍有直接数值，死亡主要增加击杀计数，尚未形成经验/金币链路。
- `ArenaPrototype.cs` 直接维护 HP、对局时间、输入、移动和重开；`Config.cs` 从独立组件读取部分配置，但运行时职责仍集中在 Arena。
- `Skills.cs` 已有 `FinishSkill` 和冷却记录，适合接入结束事件与技能急速；仍需逐个核查防御波、追加斩击与剑气是否真正结束。
- 计时混用 `elapsed × ClockRate`、`Time.time` 与 `Time.fixedTime`。极限闪避、DOT、暂停与商店不能各自改时间而缺少统一约定。
- `ArenaPlayerAnimation` 已拆出到玩家外观，移动配置、敌人配置、技能配置也已有独立组件，M6 应延续这一结构。
- 工作区存在未提交的场景、地面及动画改动；实施时保留这些修改，不以旧提交覆盖。

## 3. 用户补充定稿（2026-11-15）

以下决定覆盖 V0.5 对应条款：A 点按 CD 保留 2.5s；升级碎片随等级调整为 2～3 片，取消金色保底；增加武器背包栏，升级卡可获取武器，重复获取转为熟练度，直到满级；护盾初始生成容量 5；彩色暴伤每片 +15 个百分点（150% → 165%）；每片锻体价格约为 20 只普通怪物的金币收益。

沿用共享武器熟练度与累计 1/3/6 门槛。重复武器每次增加 1 点熟练度作为建议，尚非用户指定点数。满级后建议已拥有武器卡退出池，未拥有武器仍可获得。背包单武器装备，切换保留通用升级且不重置射击计时。新增背包组件与中文 UI，不继续将职责放入 Arena。

2 片升级到 3 片的等级阈值尚未指定，放入 Inspector 等级奖励表；护盾 5 指解锁后的基础容量，不是开局自带护盾。价格基线 = 普通怪单次金币 × 20，普通怪掉 1 金币时为 20 金币/片，倍率可调。

| 问题 | 状态 | 规则或建议 |

| 升级路径 | 玩家选路径或系统指定尚未确定 | 玩家每次升级选择“三选一能力卡”或“按等级获得 2～3 片碎片” |

| 武器切换 | 背包与升级获取武器已定 | 新武器加入背包，可更替；重复获取转共享熟练度直到满级 |

| 护盾 | 容量已定；补充与破盾计时仍为建议 | 基础容量 5；每周期补满；不叠加；破盾不重置计时；首片等待 15s |
| 敌方护盾 | 首批是否加入未定 | 首个闭环暂不加入；护盾击破碎片不进候选池 |
| 商店 | 单片价格已定，购买呈现形式未定 | 每片约 20 普通怪金币收益；建议单抽可多次买，无金色保底 |
| 飞镖返程 | 返程伤害已确认 | 20% 攻击力乘弹丸伤害系数，每枚返程飞镖对每名敌人最多命中一次；到达时确定第二段旋转中心 |
| 飞刀 DOT | tick、伤害快照、换武器后状态未定 | 0.5s/tick；刷新不重置 tick；已有 DOT 不因换武器消失；快照口径单独冻结 |
| 最大生命成长 | 增加上限是否回复当前 HP 未写 | 增加上限时增加等量当前 HP，并限制到上限 |
| 传送阵弹丸 | 避让不等于无敌 | 进入前照常受伤；成功进入后冻结战斗，已发弹丸保留 |

经验表需从公式自动生成，避免手填误差，例如 L=3 时公式为 ceil(40+32+5×2^1.7)=89，而后续各行也需同样核对。经济数值均为基线，不能仅凭面板倍率定平衡。

## 4. 结构与 Inspector

沿用现有 GameScene 中文子物体组织，不把 M6 的配置或逻辑继续塞进 Arena，也不只是增加同一 partial class 的文件。

```text
Arena（入口、引用装配及旧系统适配）
├─ 系统：对局状态 / 时间与暂停 / 场景流转
├─ 玩家
│  ├─ 功能：属性 / 生命护盾 / 移动 / 自动武器 / 武器背包
│  └─ 外观：现有动画 / 护盾表现 / 受伤反馈
├─ 战斗：伤害结算 / 投射物与状态效果
├─ 技能：保留六组技能；接属性、结束事件与冷却控制
├─ 敌人：行为配置 / 奖励档位 / 生成 / 死亡奖励
├─ 成长：经验等级 / 构筑状态 / 能力卡 / 碎片奖励
├─ 经济：本局钱包 / 商人传送阵
├─ 界面：HUD / 属性面板 / 升级选择 / 武器背包栏 / 方向指引
└─ 运行时：敌人 / 弹丸 / 掉落物 / 特效
ShopScene：商店界面 / 购买服务 / 返回控制
```

静态定义用 ScriptableObject，运行时层数、进度、抽取结果独立存储；不改写资产。配置组件按功能、外观、音效、调试分组，中文 Inspector 名称与 Tooltip，保留图标、材质、纹理、特效 Prefab、音效及音量入口。UI 保存为可选中的场景对象，编辑模式可以预览。场景生成工具同步维护新引用，避免重建后组件丢失。

## 5. 开发顺序与验收

### P0：锁定边界、计时与接入点

先记录现有六技能行为与场景引用，标出伤害入口、技能结束和对象回收事件。定义战斗时钟、玩家动作时钟、UI 时钟：保留子弹时间的既有速度差异，完全暂停时冻结全部玩法计时和物理，UI 仍能操作。暂停原因可叠加，关闭升级界面不得解除商店暂停。

验收：现有技能、近战红色预警、极限闪避、移动动画绑定不回退；不需一次性重写整个 Arena。

### P1 / M6.1：属性、伤害、冷却与护盾

建立 PlayerStats、DamageResolver、HealthShieldState、CooldownController。先定义来源标签（普攻直击、旋转、流血、反弹、主动技能），明确暴击和吸血资格；按实际 HP 损失计算吸血，护盾与过量伤害不产生额外吸血。支持小数伤害/回复，避免低伤 DOT 被整数截断。

统一攻击力只乘一次，现有技能伤害仍作基础值；区分“现有 20 点弹丸伤害”和“新武器 100% ATK”，不能直接混用。检查所有技能派生效果完成后才启动 CD，中断、死亡不重复结算。属性面板先可调试验证。

验收：急速 0/20/50/100 的 2.5s、8s、12s公式；融合只冷却两个参与按钮；已开始 CD 不追溯；护盾解锁、周期、破盾和死亡重开正确。

### P2 / M6.2：死亡奖励、钱包与升级队列

行为与奖励档位分开配置；死亡事件先锁定再发放一次，使用池实例的生成代次区分敌人生命周期。经验球、金币池化，可磁吸；经验溢出保留，多级升级排队。HUD 接经验、等级、金币、护盾。

验收：四档 100% 金币；多段同帧击杀与池复用不重复发奖；升级队列不丢失，重开完全清空。

### P3 / M6.3a：最小可玩构筑闭环

先做飞镖 +0、三种通用能力卡与武器等级状态，再做升级双路径、三选一和按等级领取 2～3 片碎片 UI。能力卡设置最大等级、前置、互斥与可重复规则；候选不足三张或卡池耗尽需明确回退为可用碎片奖励。本批数量和随机品质先锁定（无金色保底），属性逐次按已获得前置生成并锁定；按钮重复点击不重复领奖。

银/金六项、彩色七项严格分池，达到有效上限的属性过滤。无敌方护盾时不出击破卡；没解锁护盾生成时不出容量卡。

验收：熟练累计 1/3/6 升级，满级移出池；同批先获得生成效率后才可出现容量；正确显示本批 2～3 片进度，验证等级阈值，不显示保底。先让一局能走通再扩展武器。

### P4 / M6.3b：三武器完整 +0～+3

顺序：飞镖穿透/旋转/返程 → 飞刀叠层/刷新/撕裂/暴击 → 弓箭速度伤害/分裂/索敌。武器卡首次获取加入背包，重复获取转共享熟练；背包可更替已拥有武器，满级过滤无效重复奖励。换武器保留共享熟练和通用升级。投射物持有来源、发射序号与轮次 ID；弓箭轮次命中按敌人生成代次计数，关联弹丸全部结束再回收。

验收：飞镖旋转 4/8 tick；飞刀各级满层系数 150%/250%，已有满层再命中才撕裂；弓箭不递归分裂，子箭满速重置，同轮递减到 10% 下限。单轮上限 9 主箭+45 子箭；现有 Fire 的每阵营 80 上限需重新设计，避免高攻速静默吞弹。多个轮次重叠也要压测。

### P5 / M6.4：传送阵与独立商店

按战斗时间生成、可达性与避刷验证、怪物局部避让、屏幕边缘指引。Additive 加载 ShopScene，保留 GameScene 实例并隔离输入、相机和物理；进入前锁定切换状态，购物扣费与发奖作为一次交易，失败可恢复。

验收：赶路有威胁，入口不聚怪；入店时技能/DOT/子弹时间/CD全部冻结；返回原状态且入口已消耗；连续触发只加载一次，余额不足不能购买，加载失败不永久暂停。

### P6 / M6.5：存档恢复、平衡、抖音手机验收

区别“店铺往返保留内存状态”和“退出应用恢复奖励”：后者需单局检查点，保存随机结果、已领索引与构筑状态并版本化；若不做完整战斗续局，不宣称支持任意断线续局，需先冻结允许恢复的边界。

采集升级用时、每局熟练获得、能力/碎片选择比例、收入支出、武器伤害。检查 2～3 片碎片与一张能力卡的收益，以及约 20 普通怪收益购买一片的节奏，+3 的六张熟练是否能在预期局长内形成。Unity 验证后重新导出 DouyinM5/tt-minigame 并手机测试，关注高攻速分裂、DOT、大量掉落、切店、切后台与内存。

## 6. 验证方式与完成标准

- EditMode：属性/伤害公式、经验、熟练门槛、卡池条件、等级碎片数量、重复武器熟练度、价格换算、弓箭衰减等纯规则。
- PlayMode：技能结束仅一次、DOT刷新、对象池复用、暂停恢复、重复领奖/购物、死亡重开。
- 人工：六技能回归、UI安全区与中文可读性、Inspector调参、ShopScene来回；抖音真机记录设备与帧率/内存，不把编辑器通过当作手机通过。
- 每阶段交付可运行场景、独立配置与验收记录。M6 完成必须包括完整单局循环、三武器 +3、商店返回和真机验证。

P0～P4 交付与调试入口见《M6_P0-P4开发与调试.md》。原型采用 6 级起奖励三片碎片、重复武器增加 1 点共享熟练度，均可调。当前验证覆盖 Unity 编译与玩法集成，抖音真机性能验收留在 P6。
